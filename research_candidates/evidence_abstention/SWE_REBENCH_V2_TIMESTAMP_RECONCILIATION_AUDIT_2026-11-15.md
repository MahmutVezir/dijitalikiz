# SWE-rebench V2 — row-level GitHub timestamp reconciliation

**Audit date:** 15 November 2026  
**Scope:** The 96 historical primary project candidates and 17 project-level reserves selected on 12 November 2026. This is a metadata provenance audit only.

## Decision

The old 96-primary / 17-reserve cohort was generated by interpreting timezone-naive strings in the pinned filtered Parquet as UTC. That assumption was not established by the dataset schema. I therefore compared each of the 113 selected issue/PR records with the corresponding authoritative GitHub issue API `created_at` value and preserved every row in:

`SWE_REBENCH_V2_TIMESTAMP_RECONCILIATION_REGISTER_2026-11-15.csv`

Register SHA-256: `01f1ded07230cbb78943cecd00977dc28c411bfd3c7cac376f3d09b815371fde`

## Frozen source and method

- Dataset: `PrimeIntellect/SWE-rebench-V2-Filtered-Verified`
- Pinned Parquet revision: `fb9aa226b2ce37c708ea7732e7b980abacdadb67`
- Pinned Parquet SHA-256: `7416e352008b35480c82610cf4f5edf160dd269ed6bf382a22bd4c17daed24b9`
- Historical cohort: 96 primary candidate projects + 17 project reserves
- API source: GitHub issue endpoint for each exact repository/issue number; moved repositories were resolved through stable repository IDs.
- Comparison: exact UTC API timestamp versus the historical candidate CSV timestamp; delta is API time minus dataset time in seconds.
- Cutoff: `2024-09-20T00:00:00Z`.

1. `MarketSquare/robotframework-robocop#1374` — prior target debugging/reproduction; see [PR #193](https://github.com/MahmutVezir/dijitalikiz/pull/193).

After excluding these two prior-exposure projects and holding the one-second discrepancy, the selected records provide **110 date-verified project candidates**: 93 from the historical primary set and 17 from the project-reserve set.

These 110 are still candidates, not accepted cases. They have not passed exact source-license review, fork/ancestry independence review, reproducible buggy-fail/fixed-pass execution, Panel A ground-truth adjudication, Panel B evidence-tier review, or independent external audit.

## What this audit does not establish

- It does not audit all 6,272 rows in the dataset or every one of the 148 within-project alternate issue records.
- It does not prove the transformation lineage of the timezone-naive Parquet strings. It establishes the authoritative API timestamps only for the 113 selected records.
- It does not validate any defect, root cause, source license, evidence packet, or model output.
- It does not authorize source checkout, upstream test execution, model loading, inference, fine-tuning, or training.
- The historical 96-row cohort remains a historical artifact. Any new final sample must be regenerated under a new versioned seed from API-verified candidates; old hashes must not be overwritten.

## Reproducibility

The row-level register contains the dataset timestamp, GitHub API timestamp, delta, match status, exact issue/PR URL, selection role, and API lookup mode for all 113 records. Structural validation must check 113 unique IDs, 112 exact matches, the single named one-second discrepancy, and zero unverified or other-mismatch rows.

**Conclusion:** The timezone assumption is now checked against authoritative GitHub metadata for all 113 selected project candidates. The timestamp sub-gate may be considered satisfied for this selected set only. The dataset-validation and model-execution gates remain open.
